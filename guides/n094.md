# N094 — Security Operations - Cortex Management Audit Timeline

Returns one day of Cortex management-audit records with actor, host, category, result and severity context. Preserves reported outcomes and supports administrative review without treating every audit record as a successful configuration change.

Proposal: **OP-024**. Category: **Security Operations / Cortex Audit**.

Artifact: **QUERY_CANDIDATE**. Product/surface: Cortex XSIAM / Interactive XQL Search. Tenant release, full-query compiler acceptance and execution: **UNVERIFIED / NOT RUN**.

[Query file](../queries/security-operations/cortex-audit/n094-security-operations-cortex-management-audit-timeline.xql)

## Objective and interpretation

Broad audit timeline across reported categories, not a guarantee that every record represents a completed change.

Output grain: One retained source event or explicitly described aggregate/correlation row.
Timeframe: 1d unless explicitly stated in the body

## Source and field contract

Sources: `["management_auditing"]`.

Every schema token must resolve to an inspected field, expression or source with the stated type and meaning. A normalized source contract may require telemetry ingestion, parsing or a separately reviewed view; replacing names alone cannot create missing evidence. Preserve nulls. Verify timezone, identity namespaces, provider/channel, event outcomes, source completeness and row multiplicity.

No schema binding tokens. Review the actual field population, timeframe and source access before editor use.

## Pipeline and result semantics

Read the stages in order: the source and early filters establish the population; alter creates explicitly typed aliases; joins/union introduce related evidence; comp/windowcomp/dedup change row cardinality where present; the final projection, sort and limit define displayed rows. A result limit does not bound scanning or join work. Check the identity and time predicates in each subquery against the binding contract.

Estimated cost: MEDIUM. Bounded lookback and early filters; result caps do not bound upstream scanning. No measured performance claim.

## Limitations and tuning

- Category/result values are deliberately not guessed; enrich object/description context only after confirming the remaining source fields.
- Retention, access and missing collection can hide activity. Empty results are not proof of absence.
- A final result limit does not cap upstream work. Full-query compiler and execution acceptance remain NOT RUN.

## Acceptance scenarios — NOT RUN

- Positive: success and failure records both remain with raw result.
- Negative: records outside the one-day window are excluded.
- Null: absent actor/host remains visible rather than relabeled.
- Edge: different categories at the same timestamp remain separate rows.

These scenarios are plans for representative source fixtures and bounded tenant runs. They have not been executed in Cortex. First inspect the bound schema, then compile the complete body, then exercise positive, benign, negative, null and boundary cases. Do not promote this interactive hunt directly to BIOC/correlation without reviewing that surface.

Independent static review: **PASS**. Full-query C/E: **NOT RUN / NOT RUN**. Static review cannot establish source population or detection effectiveness.
