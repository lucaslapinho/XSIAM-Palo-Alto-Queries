# N071 — Threat Hunting - AWS Access Key Creation and First Observed Use

Tracks AWS IAM access-key creation and the first matching use visible within the bounded window using only non-secret credential identifiers in the explicit projection. Keeps unmatched creations for review and distinguishes legitimate rotation from suspicious additional credentials.

Proposal: **TH-047**. Category: **Threat Hunting / Cloud Credentials**.

Artifact: **SCHEMA_BINDING_TEMPLATE**. Product/surface: Cortex XSIAM / Interactive XQL Search. Tenant release, full-query compiler acceptance and execution: **UNVERIFIED / NOT RUN**.

[Query file](../queries/threat-hunting/cloud-credentials/n071-threat-hunting-aws-access-key-creation-and-first-observed-use.xql)

## Objective and interpretation

AWS access-key branch; first observed use is limited by collection and the one-day query window, not first-ever use.

Output grain: One retained source event or explicitly described aggregate/correlation row.
Timeframe: 1d unless explicitly stated in the body

## Source and field contract

Sources: `["{{AWS_ACCESS_KEY_USE_EVENTS}}", "{{AWS_AUDIT_DATASET}}"]`.

Every schema token must resolve to an inspected field, expression or source with the stated type and meaning. A normalized source contract may require telemetry ingestion, parsing or a separately reviewed view; replacing names alone cannot create missing evidence. Preserve nulls. Verify timezone, identity namespaces, provider/channel, event outcomes, source completeness and row multiplicity.

- **AWS_AUDIT_DATASET** — Dataset identifier: verified AWS CloudTrail source; one CloudTrail event per row. Management/data-event selection and account/region scope must be established.
- **AWS_EVENT_TIME** — DATETIME expression: correctly parsed CloudTrail eventTime, not a guessed timestamp unit.
- **AWS_EVENT_JSON** — STRING expression: one original CloudTrail JSON event object. Do not bind an outer Records array or double-encode a JSON string.
- **AWS_ACCESS_KEY_USE_EVENTS** — Dataset identifier: tenant-verified source with the row grain and collection requirements described below.
- **AWS_KEY_USE_TIME** — DATETIME: attributed AWS API use time.
- **AWS_USED_KEY_ID** — STRING: userIdentity.accessKeyId of the caller; non-secret identifier.
- **AWS_KEY_USE_ACCOUNT** — STRING: owning identity account, compatible with the creation account; do not substitute recipient resource account for cross-account use.
- **AWS_KEY_USE_EVENT** — STRING: observed API event name.
- **AWS_KEY_USE_SOURCE** — STRING nullable: caller address or AWS service context.

## Limitations and tuning

- Other credential types/providers require separate lifecycle mappings. Generated raw/system columns may remain available in the query UI; inspect exports before distributing results. No secret access key is explicitly extracted.
- Comparisons preserve case. Bind normalized enum values exactly as shown, normalize Windows case-insensitive paths consistently on both sides, and preserve case for Linux paths, cloud resource names and opaque identifiers. Correlation bounds use whole-second precision; subsecond boundary interpretation requires an explicit tenant check.
- Retention, access and missing collection can hide activity. Empty results are not proof of absence.
- A final result limit does not cap upstream work. Full-query compiler and execution acceptance remain NOT RUN.

## Acceptance scenarios — NOT RUN

- Positive: matching non-secret key ID and owning account link creation to later use.
- Negative: use before creation or under a different owning account does not match.
- Null: created key without visible use remains with zero matched rows.
- Edge: a cross-account resource call must be matched by credential owner, not recipient resource account.

These scenarios are plans for representative source fixtures and bounded tenant runs. They have not been executed in Cortex. First inspect the bound schema, then compile the complete body, then exercise positive, benign, negative, null and boundary cases.
