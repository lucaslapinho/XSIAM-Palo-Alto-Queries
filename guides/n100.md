# N100 — Investigation - Kubernetes Audit Timeline with Time-Valid Workload Context

Presents response-stage Kubernetes audit events for one cluster and adds workload context only when cluster, stable object UID and inventory validity match. Keeps unmatched audit events visible and avoids assigning current workload names retrospectively to recreated objects.

Proposal: **OP-030**. Category: **Investigation / Kubernetes Audit**.

Artifact: **SCHEMA_BINDING_TEMPLATE**. Product/surface: Cortex XSIAM / Interactive XQL Search. Tenant release, full-query compiler acceptance and execution: **UNVERIFIED / NOT RUN**.

[Query file](../queries/investigation/kubernetes-audit/n100-investigation-kubernetes-audit-timeline-with-time-valid-workload-context.xql)

## Objective and interpretation

One audit-stage/workload match, or an unmatched audit event. The inventory must have at most one applicable row per object UID/time.

Output grain: One retained source event or explicitly described aggregate/correlation row.
Timeframe: 1d unless explicitly stated in the body

## Source and field contract

Sources: `["{{KUBERNETES_AUDIT_DATASET}}", "{{KUBERNETES_WORKLOAD_IDENTITY_HISTORY}}"]`.

Every schema token must resolve to an inspected field, expression or source with the stated type and meaning. A normalized source contract may require telemetry ingestion, parsing or a separately reviewed view; replacing names alone cannot create missing evidence. Preserve nulls. Verify timezone, identity namespaces, provider/channel, event outcomes, source completeness and row multiplicity.

- **CLUSTER_TO_REVIEW** — Quoted STRING literal: one stable collected cluster identity.
- **KUBERNETES_AUDIT_DATASET** — Dataset identifier: verified Kubernetes audit source; one audit event/stage per row.
- **KUBERNETES_EVENT_TIME** — DATETIME expression: parsed audit stageTimestamp or requestReceivedTimestamp with the chosen semantics retained.
- **KUBERNETES_CLUSTER_ID** — STRING expression: stable cluster identity supplied by trusted collection metadata, not object namespace alone.
- **KUBERNETES_EVENT_JSON** — STRING expression: one original Kubernetes audit Event JSON object. Request/response bodies depend on the audit policy.
- **KUBERNETES_WORKLOAD_IDENTITY_HISTORY** — Dataset identifier: tenant-verified source with the row grain and collection requirements described below.
- **WORKLOAD_CLUSTER** — STRING: same stable cluster key.
- **WORKLOAD_OBJECT_UID** — STRING: audited object UID; pre-resolve ownerReferences only with time-valid resource UID evidence.
- **WORKLOAD_VALID_FROM** — DATETIME: inventory validity start inclusive.
- **WORKLOAD_VALID_UNTIL** — DATETIME: validity end exclusive.
- **WORKLOAD_KIND** — STRING: resolved workload kind.
- **WORKLOAD_NAME** — STRING: resolved workload display name.
- **WORKLOAD_NODE_NAME** — STRING nullable: node observed for this workload/pod at that time.

## Limitations and tuning

- Objects without UIDs, absent workload histories and long-running stream completion gaps remain visible as limitations. No runtime execution is inferred from the API record.
- Comparisons preserve case. Bind normalized enum values exactly as shown, normalize Windows case-insensitive paths consistently on both sides, and preserve case for Linux paths, cloud resource names and opaque identifiers. Correlation bounds use whole-second precision; subsecond boundary interpretation requires an explicit tenant check.
- Retention, access and missing collection can hide activity. Empty results are not proof of absence.
- A final result limit does not cap upstream work. Full-query compiler and execution acceptance remain NOT RUN.

## Acceptance scenarios — NOT RUN

- Positive: matching object UID and validity interval enrich the event.
- Negative: same object name with a different UID must not enrich it.
- Null: missing object UID preserves the audit row with no inventory match.
- Edge: an object moved/recreated after the event does not acquire current context.
