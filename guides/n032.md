# N032 — Threat Hunting - New Services in Profile or Temporary Paths

Preserves successful service-install records whose configured executable path matches a profile/temporary heuristic and adds first observed same-path process-start context within one hour.

Proposal: **TH-007**. Category: **Threat Hunting / Persistence**.

Artifact: **SCHEMA_BINDING_TEMPLATE**. Product/surface: Cortex XSIAM / Interactive XQL Search. Tenant release, full-query compiler acceptance and execution: **UNVERIFIED / NOT RUN**.

Full installation-to-execution template. A same-path start is corroboration and does not prove the service manager launched it.

## Pipeline and result semantics

Read the stages in order: the source and early filters establish the population; alter creates explicitly typed aliases; joins/union introduce related evidence; comp/windowcomp/dedup change row cardinality where present; the final projection, sort and limit define displayed rows. A result limit does not bound scanning or join work. Check the identity and time predicates in each subquery against the binding contract.

Estimated cost: MEDIUM. Bounded lookback and early filters; result caps do not bound upstream scanning. No measured performance claim.

## Limitations and tuning

- Service configuration parsing must resolve quoted paths, arguments and variables without treating DLL arguments as the executable.
- First observed is bounded by collected one-day data and a one-hour post-install interval; paths do not establish ACL writability.
- No tenant compilation or execution. Validate nulls, access, retention and source collection before interpreting empty results.
- A terminal limit bounds displayed output, not upstream scans or join multiplicity.
