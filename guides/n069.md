# N069 — Threat Hunting - Sustained CPU Use with Attributed Mining Communication

Correlates sustained high CPU samples with independently identified mining communication from the same process within a fixed 15-minute interval. Requires genuine resource metrics and protocol attribution; software names, ports and EDR row counts do not establish cryptomining.

Proposal: **TH-045**. Category: **Threat Hunting / Resource Abuse**.

Artifact: **SCHEMA_BINDING_TEMPLATE**. Product/surface: Cortex XSIAM / Interactive XQL Search. Tenant release, full-query compiler acceptance and execution: **UNVERIFIED / NOT RUN**.

[Query file](../queries/threat-hunting/resource-abuse/n069-threat-hunting-sustained-cpu-use-with-attributed-mining-communication.xql)

## Objective and interpretation

One high-utilization process/window and attributed protocol event pair; approved compute/mining must be considered.

Output grain: One retained source event or explicitly described aggregate/correlation row.
Timeframe: 1d unless explicitly stated in the body

## Source and field contract

Sources: `["{{IDENTIFIED_MINING_PROTOCOL_EVENTS}}", "{{PROCESS_RESOURCE_METRICS}}"]`.

Every schema token must resolve to an inspected field, expression or source with the stated type and meaning. A normalized source contract may require telemetry ingestion, parsing or a separately reviewed view; replacing names alone cannot create missing evidence. Preserve nulls. Verify timezone, identity namespaces, provider/channel, event outcomes, source completeness and row multiplicity.

- **MIN_SPAN_SECONDS** — INTEGER 600..899: minimum first-to-last sample duration in the 15-minute interval.
- **MAX_SAMPLE_GAP_SECONDS** — Positive INTEGER: maximum admitted gap between consecutive samples; set to the validated collection cadence plus reviewed jitter, for example 90 for a 60-second collector.
- **MIN_CPU_PERCENT** — Numeric literal 0..100: workload-reviewed sustained CPU threshold.
- **MIN_SAMPLES** — INTEGER at least 3: minimum metric samples in a 15-minute window; source cadence must be known.
- **PROCESS_RESOURCE_METRICS** — Dataset identifier: tenant-verified source with the row grain and collection requirements described below.
- **RESOURCE_METRIC_TIME** — DATETIME: actual sampled utilization time.
- **RESOURCE_ENDPOINT** — STRING: stable host/workload identity.
- **RESOURCE_PROCESS** — STRING: stable process instance, same namespace as attributed network events.
- **RESOURCE_CPU_PERCENT** — FLOAT: normalized percentage of the reviewed CPU capacity, 0..100; specify per-core versus whole-host denominator.
- **RESOURCE_METRIC_KIND** — STRING: normalized cpu_percent; exclude unlike units or counters.
- **IDENTIFIED_MINING_PROTOCOL_EVENTS** — Dataset identifier: tenant-verified source with the row grain and collection requirements described below.
- **MINING_NETWORK_TIME** — DATETIME: actual attributed protocol observation time.
- **MINING_NETWORK_ENDPOINT** — STRING: same endpoint namespace.
- **MINING_NETWORK_PROCESS** — STRING: same process instance namespace.
- **MINING_PROTOCOL_IDENTIFIED** — BOOLEAN: true only from independently validated mining protocol/content classification; an indicator match, destination reputation or common port alone cannot set this flag.
- **MINING_POOL_DESTINATION** — STRING: observed pool/service destination.
- **MINING_PROTOCOL_EVIDENCE** — STRING: safe evidence label; preserve attribution and confidence.

## Limitations and tuning

- Sampling gaps, denominator changes, GPU-only mining and unattributed proxy traffic can be missed. Duplicate metric samples must be resolved before binding.
- Comparisons preserve case. Bind normalized enum values exactly as shown, normalize Windows case-insensitive paths consistently on both sides, and preserve case for Linux paths, cloud resource names and opaque identifiers. Correlation bounds use whole-second precision; subsecond boundary interpretation requires an explicit tenant check.
- Retention, access and missing collection can hide activity. Empty results are not proof of absence.
- A final result limit does not cap upstream work. Full-query compiler and execution acceptance remain NOT RUN.

## Acceptance scenarios — NOT RUN

- Positive: enough sustained CPU samples plus same-process mining protocol evidence match.
- Negative: busy approved compute with no mining communication does not match.
- Null: absent process attribution cannot correlate.
- Edge: a protocol event from another process does not substantiate the metric; three clustered samples or a long sampling gap must fail the sustained-span criteria.

These scenarios are plans for representative source fixtures and bounded tenant runs. They have not been executed in Cortex. First inspect the bound schema, then compile the complete body, then exercise positive, benign, negative, null and boundary cases. Do not promote this interactive hunt directly to BIOC/correlation without reviewing that surface.
