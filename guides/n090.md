# N090 — Investigation - Privileged Access to Time-Qualified Critical Assets

Correlates successful asset-access records with effective privileged entitlements and critical-asset classification valid at the event time. Requires explicit identity and asset contracts and returns entitlement context without assuming that every privileged access is inappropriate.

Proposal: **OP-020**. Category: **Investigation / Privileged Access**.

Artifact: **SCHEMA_BINDING_TEMPLATE**. Product/surface: Cortex XSIAM / Interactive XQL Search. Tenant release, full-query compiler acceptance and execution: **UNVERIFIED / NOT RUN**.

## Objective and interpretation

One successful access/entitlement match; multiple legitimate roles may produce multiple rows.

Output grain: One retained source event or explicitly described aggregate/correlation row.
Timeframe: 1d unless explicitly stated in the body

## Source and field contract

Sources: `["{{ASSET_ACCESS_EVENTS}}", "{{CRITICAL_ASSET_HISTORY}}", "{{PRIVILEGED_ENTITLEMENT_HISTORY}}"]`.

Every schema token must resolve to an inspected field, expression or source with the stated type and meaning. A normalized source contract may require telemetry ingestion, parsing or a separately reviewed view; replacing names alone cannot create missing evidence. Preserve nulls. Verify timezone, identity namespaces, provider/channel, event outcomes, source completeness and row multiplicity.

- **ASSET_ACCESS_EVENTS** — Dataset identifier: tenant-verified source with the row grain and collection requirements described below.
- **ACCESS_TIME** — DATETIME: actual asset/service access timestamp.
- **ACCESS_EVENT_KEY** — STRING: stable access-record identity.
- **ACCESS_PRINCIPAL_ID** — STRING: stable authority-qualified principal.
- **ACCESS_ASSET_ID** — STRING: stable asset identity, not a hostname-only guess.
- **ACCESS_ACTION** — STRING: original authenticated access operation.
- **ACCESS_SUCCESS** — BOOLEAN: verified successful access outcome; null remains unknown.
- **PRIVILEGED_ENTITLEMENT_HISTORY** — Dataset identifier: tenant-verified source with the row grain and collection requirements described below.
- **PRIVILEGED_PRINCIPAL_ID** — STRING: same authority-qualified principal namespace as access.
- **PRIVILEGED_ASSET_ID** — STRING: entitlement scope resolved to a specific asset.
- **PRIVILEGE_VALID_FROM** — DATETIME: entitlement validity start inclusive.
- **PRIVILEGE_VALID_UNTIL** — DATETIME: entitlement validity end exclusive; bind an explicit future bound for open intervals.
- **PRIVILEGE_ROLE** — STRING: reviewed effective privileged entitlement.
- **CRITICAL_ASSET_HISTORY** — Dataset identifier: tenant-verified source with the row grain and collection requirements described below.
- **CRITICAL_ASSET_ID** — STRING: same stable asset namespace.
- **CRITICAL_VALID_FROM** — DATETIME: criticality validity start inclusive.
- **CRITICAL_VALID_UNTIL** — DATETIME: criticality validity end exclusive.
- **CRITICAL_OWNER** — STRING: accountable asset owner.

## Limitations and tuning

- Inventory history must be unique per entitlement interval; do not apply current privileges retrospectively.
- Comparisons preserve case. Bind normalized enum values exactly as shown, normalize Windows case-insensitive paths consistently on both sides, and preserve case for Linux paths, cloud resource names and opaque identifiers. Correlation bounds use whole-second precision; subsecond boundary interpretation requires an explicit tenant check.
- Retention, access and missing collection can hide activity. Empty results are not proof of absence.
- A final result limit does not cap upstream work. Full-query compiler and execution acceptance remain NOT RUN.

## Acceptance scenarios — NOT RUN

- Positive: access during both privilege and criticality validity intervals matches.
- Negative: failed access or expired privilege is excluded.
- Null: missing principal or asset identity cannot match.
- Edge: current privilege granted after the event must not reclassify that event.

These scenarios are plans for representative source fixtures and bounded tenant runs. They have not been executed in Cortex. First inspect the bound schema, then compile the complete body, then exercise positive, benign, negative, null and boundary cases.
