# N096 — Security Operations - Cortex Response Requests and Terminal Outcomes

Links Cortex response requests to terminal audit records by stable action and endpoint identity within 24 hours. Preserves requests without a terminal record and reports original outcomes; no response action is executed by this query.

Proposal: **OP-026**. Category: **Security Operations / Response Audit**.

Artifact: **SCHEMA_BINDING_TEMPLATE**. Product/surface: Cortex XSIAM / Interactive XQL Search. Tenant release, full-query compiler acceptance and execution: **UNVERIFIED / NOT RUN**.

[Query file](../queries/security-operations/response-audit/n096-security-operations-cortex-response-requests-and-terminal-outcomes.xql)

## Objective and interpretation

One request/terminal pair or unmatched request; multiple terminal records remain visible for reconciliation.

Output grain: One retained source event or explicitly described aggregate/correlation row.
Timeframe: 1d unless explicitly stated in the body

## Source and field contract

Sources: `["{{RESPONSE_AUDIT_EVENTS}}"]`.

Every schema token must resolve to an inspected field, expression or source with the stated type and meaning. A normalized source contract may require telemetry ingestion, parsing or a separately reviewed view; replacing names alone cannot create missing evidence. Preserve nulls. - **RESPONSE_ENDPOINT_ID** — STRING: exact target endpoint identity.
- **RESPONSE_ACTOR** — STRING nullable: requesting actor.

## Pipeline and result semantics

Read the stages in order: the source and early filters establish the population; alter creates explicitly typed aliases; joins/union introduce related evidence; comp/windowcomp/dedup change row cardinality where present; the final projection, sort and limit define displayed rows. A result limit does not bound scanning or join work. Check the identity and time predicates in each subquery against the binding contract.

Estimated cost: MEDIUM. Bounded lookback and early filters; result caps do not bound upstream scanning. No measured performance claim.

## Limitations and tuning

- A completion record is not necessarily success. Window boundaries can hide terminal events; unmatched is not automatically failed or timed out.
- Comparisons preserve case. Bind normalized enum values exactly as shown, normalize Windows case-insensitive paths consistently on both sides, and preserve case for Linux paths, cloud resource names and opaque identifiers. Correlation bounds use whole-second precision; subsecond boundary interpretation requires an explicit tenant check.
- Retention, access and missing collection can hide activity. Empty results are not proof of absence.
- A final result limit does not cap upstream work. Full-query compiler and execution acceptance remain NOT RUN.

## Acceptance scenarios — NOT RUN

- Positive: matching action+endpoint terminal event after request joins.
- Negative: another endpoint or earlier terminal event does not join.
- Null: request without completion remains visible.
- Edge: retries with distinct action IDs remain separate.

These scenarios are plans for representative source fixtures and bounded tenant runs. They have not been executed in Cortex. First inspect the bound schema, then compile the complete body, then exercise positive, benign, negative, null and boundary cases.
