# N063 — Cyber Hygiene - Remote Desktop Observations without a Matching Scoped Approval

Compares verified remote-desktop software observations with time-valid approvals scoped to endpoint, principal, product and version. Returns unmatched observations for policy review and keeps inventory evidence distinct from process execution.

Proposal: **TH-039**. Category: **Cyber Hygiene / Software Approval**.

Artifact: **SCHEMA_BINDING_TEMPLATE**. Product/surface: Cortex XSIAM / Interactive XQL Search. Tenant release, full-query compiler acceptance and execution: **UNVERIFIED / NOT RUN**.

## Objective and interpretation

Unmatched approval candidate. It becomes an unapproved-use conclusion only if the approval inventory is authoritative and complete.

Output grain: One retained source event or explicitly described aggregate/correlation row.
Timeframe: 1d unless explicitly stated in the body

## Source and field contract

Verify timezone, identity namespaces, provider/channel, event outcomes, source completeness and row multiplicity.

- **REMOTE_DESKTOP_SOFTWARE_OBSERVATIONS** — Dataset identifier: tenant-verified source with the row grain and collection requirements described below.
- **REMOTE_SOFTWARE_TIME** — DATETIME: actual execution observation or freshness-qualified inventory snapshot.
- **REMOTE_SOFTWARE_ENDPOINT** — STRING: stable endpoint ID.
- **REMOTE_SOFTWARE_USER** — STRING: stable user/service identity applicable to this observation.

- **APPROVED_ENDPOINT** — STRING: exact approved endpoint; expand group scope explicitly before binding.
- **APPROVED_PRINCIPAL** — STRING: approved principal, no implicit any-user wildcard.

## Limitations and tuning

- Expired, missing or incompletely expanded approvals can produce candidates. Subsequent service/network/descendant pivots do not follow automatically from inventory presence.
- Comparisons preserve case. Bind normalized enum values exactly as shown, normalize Windows case-insensitive paths consistently on both sides, and preserve case for Linux paths, cloud resource names and opaque identifiers. Correlation bounds use whole-second precision; subsecond boundary interpretation requires an explicit tenant check.
- Retention, access and missing collection can hide activity. Empty results are not proof of absence.
- A final result limit does not cap upstream work. Full-query compiler and execution acceptance remain NOT RUN.

## Acceptance scenarios — NOT RUN

- Positive: verified product/version on an unapproved endpoint is returned.
- Negative: fully matching unexpired approval removes the observation.
- Null: unknown identity/version is excluded for separate data-quality handling.
- Edge: an expired or different-user approval must not suppress the result.

These scenarios are plans for representative source fixtures and bounded tenant runs. They have not been executed in Cortex.
