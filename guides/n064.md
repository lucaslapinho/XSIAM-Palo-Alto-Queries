# N064 — Threat Hunting - Large Archive Creation with Observed Input Context

Links a process observed accessing many distinct input files to a sufficiently large archive it creates, preserving sensitive-data classification context. Supports staging investigation and later transfer pivots without equating an archiver command with a completed archive.

Proposal: **TH-040**. Category: **Threat Hunting / Data Staging**.

Artifact: **SCHEMA_BINDING_TEMPLATE**. Product/surface: Cortex XSIAM / Interactive XQL Search. Tenant release, full-query compiler acceptance and execution: **UNVERIFIED / NOT RUN**.

## Objective and interpretation

One endpoint/process/archive-operation/output aggregate matched to an archive creation; thresholds are workload-dependent review criteria.

Output grain: One retained source event or explicitly described aggregate/correlation row.
Timeframe: 1d unless explicitly stated in the body

## Source and field contract

Sources: `["{{ARCHIVE_INPUT_OBSERVATIONS}}", "{{ARCHIVE_OUTPUT_CREATIONS}}"]`.

Every schema token must resolve to an inspected field, expression or source with the stated type and meaning. A normalized source contract may require telemetry ingestion, parsing or a separately reviewed view; replacing names alone cannot create missing evidence. Preserve nulls. Verify timezone, identity namespaces, provider/channel, event outcomes, source completeness and row multiplicity.

- **MIN_INPUT_FILES** — Positive INTEGER literal: tuned distinct observed input-file count.
- **MIN_ARCHIVE_BYTES** — Positive INTEGER literal: minimum created archive size in bytes.
- **ARCHIVE_INPUT_OBSERVATIONS** — Dataset identifier: tenant-verified source with the row grain and collection requirements described below.
- **ARCHIVE_INPUT_TIME** — DATETIME: observed input access timestamp.
- **ARCHIVE_ENDPOINT** — STRING: endpoint identity.
- **ARCHIVE_PROCESS** — STRING: archive-producing process instance.
- **ARCHIVE_INPUT_PATH** — STRING: observed input path, not merely a command-line mention.
- **ARCHIVE_INPUT_SENSITIVE** — BOOLEAN: true only from authoritative data/path classification.
- **ARCHIVE_INPUT_OPERATION** — STRING: unique archive operation identity, linked independently to both input observations and the output file event; never an inferred name-only relationship.
- **ARCHIVE_OUTPUT_PATH** — STRING: exact filesystem output path; preserve case for case-sensitive filesystems, normalize only within a verified case-insensitive namespace on both sides.
- **ARCHIVE_OUTPUT_CREATIONS** — Dataset identifier: tenant-verified source with the row grain and collection requirements described below.
- **ARCHIVE_CREATED_OPERATION** — STRING: independently linked archive operation identity, matching ARCHIVE_INPUT_OPERATION.
- **ARCHIVE_CREATED_TIME** — DATETIME: archive file creation/write completion.
- **ARCHIVE_CREATED_ENDPOINT** — STRING: matching endpoint.
- **ARCHIVE_CREATED_PROCESS** — STRING: actual writer process instance.
- **ARCHIVE_CREATED_PATH** — STRING: same normalized filesystem path as ARCHIVE_OUTPUT_PATH.
- **ARCHIVE_CREATED_BYTES** — INTEGER: file size in bytes, not network volume.
- **ARCHIVE_CREATED_SHA256** — STRING nullable: archive content SHA-256.

## Pipeline and result semantics

## Limitations and tuning

- Archive identification and complete input access telemetry must be established. Legitimate build/backup workloads can meet both thresholds.
- Comparisons preserve case. Bind normalized enum values exactly as shown, normalize Windows case-insensitive paths consistently on both sides, and preserve case for Linux paths, cloud resource names and opaque identifiers. Correlation bounds use whole-second precision; subsecond boundary interpretation requires an explicit tenant check.
- Retention, access and missing collection can hide activity. Empty results are not proof of absence.
- A final result limit does not cap upstream work. Full-query compiler and execution acceptance remain NOT RUN.

## Acceptance scenarios — NOT RUN

- Positive: observed inputs plus matching large output satisfy thresholds.
- Negative: command mention without observed output does not match.
- Null: absent size cannot meet the volume threshold.
- Edge: repeated reads of one file do not inflate distinct-input count.

These scenarios are plans for representative source fixtures and bounded tenant runs. They have not been executed in Cortex. First inspect the bound schema, then compile the complete body, then exercise positive, benign, negative, null and boundary cases. Do not promote this interactive hunt directly to BIOC/correlation without reviewing that surface.
