# N074 — Threat Hunting - Admitted Containers with Privileged or Host-Access Settings

Selects admitted normal, init and ephemeral container specifications with privileged execution or host-access settings. Requires normalized admitted specs and mounted-volume resolution; a requested privileged spec does not establish admission or a running container.

Proposal: **TH-050**. Category: **Threat Hunting / Kubernetes Workloads**.

Artifact: **SCHEMA_BINDING_TEMPLATE**. Product/surface: Cortex XSIAM / Interactive XQL Search. Tenant release, full-query compiler acceptance and execution: **UNVERIFIED / NOT RUN**.

## Objective and interpretation

One admitted container/spec observation; runtime_id is optional independent corroboration, not inferred execution.

Output grain: One retained source event or explicitly described aggregate/correlation row.

## Source and field contract

Sources: `["{{ADMITTED_KUBERNETES_CONTAINER_SPECS}}"]`.

- **ADMITTED_KUBERNETES_CONTAINER_SPECS** — Dataset identifier: tenant-verified source with the row grain and collection requirements described below.
- **CONTAINER_ADMISSION_TIME** — DATETIME: successful admitted spec/version observation time.
- **CONTAINER_CLUSTER** — STRING: stable cluster ID.
- **CONTAINER_NAMESPACE** — STRING: namespace.
- **CONTAINER_POD_UID** — STRING: admitted pod UID, stable across same-name recreation.

- **CONTAINER_KIND** — STRING: normal/init/ephemeral; source must expand all three lists into distinct rows.
- **CONTAINER_ADMISSION_ACTOR** — STRING nullable: verified originating audit principal.
- **CONTAINER_ADMITTED_FLAG** — BOOLEAN: true only for the admitted object; request-only and denied objects must not be marked true.
- **CONTAINER_PRIVILEGED** — BOOLEAN nullable: effective securityContext.privileged with version/OS defaults resolved.
- **CONTAINER_HOST_PID** — BOOLEAN nullable: effective pod hostPID.
- **CONTAINER_HOST_IPC** — BOOLEAN nullable: effective pod hostIPC.
- **CONTAINER_HOST_NETWORK** — BOOLEAN nullable: effective pod hostNetwork.
- **CONTAINER_HOSTPATH_MOUNT** — BOOLEAN nullable: true only if this container mounts a hostPath-backed volume; do not flag unused pod volumes.

## Limitations and tuning

- Approved infrastructure often needs host access. Admission mutation, OS-specific defaults and controller-to-pod resolution must be established in the source contract.
- Comparisons preserve case. Bind normalized enum values exactly as shown, normalize Windows case-insensitive paths consistently on both sides, and preserve case for Linux paths, cloud resource names and opaque identifiers. Correlation bounds use whole-second precision; subsecond boundary interpretation requires an explicit tenant check.
- Retention, access and missing collection can hide activity. Empty results are not proof of absence.
- A final result limit does not cap upstream work. Full-query compiler and execution acceptance remain NOT RUN.

## Acceptance scenarios — NOT RUN

- Positive: admitted init container with privileged=true is included.
- Negative: denied request or unused hostPath volume does not qualify.
- Null: unknown flags are not treated as true.
- Edge: recreated pod with the same name retains a different UID; ephemeral containers are included.

These scenarios are plans for representative source fixtures and bounded tenant runs. They have not been executed in Cortex.
