# N060 — Threat Hunting - High-Cardinality DNS Name Candidates

Ranks endpoint and base-domain groups with many distinct and long DNS query names using tuned thresholds. Returns record types, responses and process context for investigation; these features alone do not prove tunneling or command and control.

Proposal: **TH-036**. Category: **Threat Hunting / DNS**.

Artifact: **SCHEMA_BINDING_TEMPLATE**. Product/surface: Cortex XSIAM / Interactive XQL Search. Tenant release, full-query compiler acceptance and execution: **UNVERIFIED / NOT RUN**.

[Query file](../queries/threat-hunting/dns/n060-threat-hunting-high-cardinality-dns-name-candidates.xql)

## Objective and interpretation

One endpoint/base-domain aggregate in the selected day; thresholds are review heuristics, not trained anomaly scores.

Output grain: One retained source event or explicitly described aggregate/correlation row.
Timeframe: 1d unless explicitly stated in the body

## Source and field contract

Sources: `["{{DNS_QUERY_EVENTS}}"]`.

Every schema token must resolve to an inspected field, expression or source with the stated type and meaning. A normalized source contract may require telemetry ingestion, parsing or a separately reviewed view; replacing names alone cannot create missing evidence. Preserve nulls. Verify timezone, identity namespaces, provider/channel, event outcomes, source completeness and row multiplicity.

- **MIN_DISTINCT_NAMES** — Positive INTEGER literal: tuned distinct full-query-name count threshold per endpoint/base-domain/day.
- **MIN_MEAN_LENGTH** — Positive numeric literal: tuned mean DNS-query-name character length threshold.
- **DNS_QUERY_EVENTS** — Dataset identifier: tenant-verified source with the row grain and collection requirements described below.
- **DNS_TIME** — DATETIME: DNS query observation time.
- **DNS_ENDPOINT_ID** — STRING: stable endpoint identity.
- **DNS_PROCESS_INSTANCE** — STRING nullable: initiating process instance, not PID alone.
- **DNS_QUERY_NAME** — STRING: full DNS name; bind a lowercase, trailing-dot-normalized value.
- **DNS_BASE_DOMAIN** — STRING: organizational/registrable domain from a validated public-suffix-aware resolver; not simply the last two labels.
- **DNS_QUERY_TYPE** — STRING: DNS record type.
- **DNS_RESPONSE_CODE** — STRING nullable: actual response code; unknown must remain null.

## Pipeline and result semantics

Read the stages in order: the source and early filters establish the population; alter creates explicitly typed aliases; joins/union introduce related evidence; comp/windowcomp/dedup change row cardinality where present; the final projection, sort and limit define displayed rows. A result limit does not bound scanning or join work. Check the identity and time predicates in each subquery against the binding contract.

Estimated cost: MEDIUM. Bounded lookback and early filters; result caps do not bound upstream scanning. No measured performance claim.

## Limitations and tuning

- DNS source must disclose whether rows are individual queries or aggregates. Public suffix normalization and legitimate CDN/security-tool behavior materially change results.
- Comparisons preserve case. Bind normalized enum values exactly as shown, normalize Windows case-insensitive paths consistently on both sides, and preserve case for Linux paths, cloud resource names and opaque identifiers. Correlation bounds use whole-second precision; subsecond boundary interpretation requires an explicit tenant check.
- Retention, access and missing collection can hide activity. Empty results are not proof of absence.
- A final result limit does not cap upstream work. Full-query compiler and execution acceptance remain NOT RUN.

## Acceptance scenarios — NOT RUN

- Positive: long, varied names under one verified base domain cross both thresholds.
- Negative: repeated queries to one name do not inflate distinct-name count.
- Null: missing base domain is excluded.
- Edge: multi-label public suffixes must group under the correct registrable domain.

These scenarios are plans for representative source fixtures and bounded tenant runs. They have not been executed in Cortex. First inspect the bound schema, then compile the complete body, then exercise positive, benign, negative, null and boundary cases. Do not promote this interactive hunt directly to BIOC/correlation without reviewing that surface.

Independent static review: **PASS**. Full-query C/E: **NOT RUN / NOT RUN**. Static review cannot establish source population or detection effectiveness.
