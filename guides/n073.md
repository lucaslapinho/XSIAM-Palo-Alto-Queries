# N073 — Threat Hunting - Kubernetes Bindings to Reviewed Privileged Roles

Finds successful binding changes whose admitted role reference resolves to a reviewed privileged role at event time. Uses cluster, role kind, name and namespace scope explicitly; request patches and role names alone do not establish effective privileges.

Proposal: **TH-049**. Category: **Threat Hunting / Kubernetes RBAC**.

Artifact: **SCHEMA_BINDING_TEMPLATE**. Product/surface: Cortex XSIAM / Interactive XQL Search. Tenant release, full-query compiler acceptance and execution: **UNVERIFIED / NOT RUN**.

[Query file](../queries/threat-hunting/kubernetes-rbac/n073-threat-hunting-kubernetes-bindings-to-reviewed-privileged-roles.xql)

## Objective and interpretation

One successful binding change and time-valid reviewed-role match; subject extraction and effective per-subject permissions are follow-up pivots.

Output grain: One retained source event or explicitly described aggregate/correlation row.
Timeframe: 1d unless explicitly stated in the body

## Source and field contract

Sources: `["{{KUBERNETES_AUDIT_DATASET}}", "{{KUBERNETES_REVIEWED_ROLE_HISTORY}}"]`.

Every schema token must resolve to an inspected field, expression or source with the stated type and meaning. A normalized source contract may require telemetry ingestion, parsing or a separately reviewed view; replacing names alone cannot create missing evidence. Preserve nulls. Verify timezone, identity namespaces, provider/channel, event outcomes, source completeness and row multiplicity.

- **KUBERNETES_AUDIT_DATASET** — Dataset identifier: verified Kubernetes audit source; one audit event/stage per row.
- **KUBERNETES_EVENT_TIME** — DATETIME expression: parsed audit stageTimestamp or requestReceivedTimestamp with the chosen semantics retained.
- **KUBERNETES_CLUSTER_ID** — STRING expression: stable cluster identity supplied by trusted collection metadata, not object namespace alone.
- **KUBERNETES_EVENT_JSON** — STRING expression: one original Kubernetes audit Event JSON object. Request/response bodies depend on the audit policy.
- **KUBERNETES_REVIEWED_ROLE_HISTORY** — Dataset identifier: tenant-verified source with the row grain and collection requirements described below.
- **ROLE_REVIEW_CLUSTER** — STRING: same stable cluster ID.
- **ROLE_REVIEW_KIND** — STRING: Role or ClusterRole, exact case.
- **ROLE_REVIEW_NAME** — STRING: exact role name, not a privileged-name substring.
- **ROLE_REVIEW_NAMESPACE** — STRING nullable: Role namespace; null/empty for ClusterRole.
- **ROLE_REVIEW_FROM** — DATETIME: reviewed resolved role-rules validity start.
- **ROLE_REVIEW_UNTIL** — DATETIME: role-rules validity end exclusive.
- **ROLE_REVIEW_HIGH_PRIVILEGE** — BOOLEAN: reviewed effective rule set is privileged; evaluate wildcards, bind/escalate/impersonate, aggregation and resource scope.
- **ROLE_REVIEW_REASON** — STRING: resolved permissions and scope rationale.

Read the stages in order: the source and early filters establish the population; alter creates explicitly typed aliases; joins/union introduce related evidence; comp/windowcomp/dedup change row cardinality where present; the final projection, sort and limit define displayed rows. A result limit does not bound scanning or join work. Check the identity and time predicates in each subquery against the binding contract.

## Limitations and tuning

- Requires RequestResponse-level body coverage sufficient for responseObject. Omitted response bodies are excluded rather than guessed from patch fragments. Role definition changes can change privileges without a binding event.
- Comparisons preserve case. Bind normalized enum values exactly as shown, normalize Windows case-insensitive paths consistently on both sides, and preserve case for Linux paths, cloud resource names and opaque identifiers. Correlation bounds use whole-second precision; subsecond boundary interpretation requires an explicit tenant check.
- Retention, access and missing collection can hide activity. Empty results are not proof of absence.
- A final result limit does not cap upstream work. Full-query compiler and execution acceptance remain NOT RUN.

## Acceptance scenarios — NOT RUN

- Positive: admitted roleRef matches a time-valid reviewed privileged role in the same cluster.
- Negative: nonprivileged or different-namespace Role does not match.
- Null: missing admitted roleRef is excluded.
- Edge: ClusterRole namespace comparison is not confused with a namespaced Role; a stale role version must not qualify.

These scenarios are plans for representative source fixtures and bounded tenant runs. They have not been executed in Cortex. First inspect the bound schema, then compile the complete body, then exercise positive, benign, negative, null and boundary cases. Do not promote this interactive hunt directly to BIOC/correlation without reviewing that surface.
