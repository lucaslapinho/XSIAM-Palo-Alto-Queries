# N061 — Threat Hunting - Periodic Identified Web Connection Candidates

Measures positive time gaps between deduplicated, application-identified web connection starts for an endpoint, process and destination. Selects sufficiently frequent low-spread intervals for review while preserving the distinction between periodicity and malicious beaconing.

Proposal: **TH-037**. Category: **Threat Hunting / Network Periodicity**.

Artifact: **SCHEMA_BINDING_TEMPLATE**. Product/surface: Cortex XSIAM / Interactive XQL Search. Tenant release, full-query compiler acceptance and execution: **UNVERIFIED / NOT RUN**.

[Query file](../queries/threat-hunting/network-periodicity/n061-threat-hunting-periodic-identified-web-connection-candidates.xql)

## Objective and interpretation

One endpoint/process/destination group with at least the configured number of positive intervals.

Output grain: One retained source event or explicitly described aggregate/correlation row.
Timeframe: 1d unless explicitly stated in the body

## Source and field contract

Sources: `["{{IDENTIFIED_WEB_CONNECTION_STARTS}}"]`.

Every schema token must resolve to an inspected field, expression or source with the stated type and meaning. A normalized source contract may require telemetry ingestion, parsing or a separately reviewed view; replacing names alone cannot create missing evidence. Preserve nulls. Verify timezone, identity namespaces, provider/channel, event outcomes, source completeness and row multiplicity.

- **MIN_INTERVALS** — INTEGER literal at least 5: minimum observed inter-arrival gaps.
- **MIN_GAP_SECONDS** — Positive numeric literal: minimum average gap of interest.
- **MAX_RELATIVE_SPREAD** — Numeric literal between 0 and 1: allowed (max_gap-min_gap)/mean_gap; tune using legitimate traffic.
- **IDENTIFIED_WEB_CONNECTION_STARTS** — Dataset identifier: tenant-verified source with the row grain and collection requirements described below.
- **WEB_START_TIME** — DATETIME: one connection/session start, not periodic traffic-statistics timestamps.
- **WEB_ENDPOINT_ID** — STRING: stable endpoint identity.
- **WEB_PROCESS_INSTANCE** — STRING: stable owning process instance.
- **WEB_CONNECTION_ID** — STRING: unique connection key within endpoint/process/window; establish lifetime before binding.
- **WEB_DESTINATION** — STRING: normalized identified web destination/domain; not a port-only application label.
- **WEB_IDENTIFIED_FLAG** — BOOLEAN: true only from protocol/application evidence, not from port 80/443 alone.

## Limitations and tuning

- Persistent sessions with repeated messages may be missed. Clock ties, connection-ID reuse and periodic telemetry statistics must be resolved before using the metric.
- Comparisons preserve case. Bind normalized enum values exactly as shown, normalize Windows case-insensitive paths consistently on both sides, and preserve case for Linux paths, cloud resource names and opaque identifiers. Correlation bounds use whole-second precision; subsecond boundary interpretation requires an explicit tenant check.
- Retention, access and missing collection can hide activity. Empty results are not proof of absence.
- A final result limit does not cap upstream work. Full-query compiler and execution acceptance remain NOT RUN.

## Acceptance scenarios — NOT RUN

- Positive: repeated independent connection starts at nearly equal gaps meet the tuned spread threshold.
- Negative: one session with many statistics rows must collapse before gap analysis.
- Null: missing stable connection or process key is excluded.
- Edge: equal timestamp gaps are discarded; no division by zero is possible.

These scenarios are plans for representative source fixtures and bounded tenant runs. They have not been executed in Cortex. First inspect the bound schema, then compile the complete body, then exercise positive, benign, negative, null and boundary cases. Do not promote this interactive hunt directly to BIOC/correlation without reviewing that surface.
